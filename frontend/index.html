System Architecture: 3NF Relational Model vs. Star Schema Data Warehouse

Key Design Decisions for Viva Voce

• Operational Schema (3NF): Pinned in operational. Normalized up to Third Normal Form to eliminate update anomalies, enforce spatial topology via PostGIS GiST bounding-box indexes, and track raw sensor telemetry.
• Data Warehouse Schema (Star Schema): Pinned in warehouse. Optimized for high-throughput OLAP analytics, multi-level ROLLUP aggregations, and windowing. Separates surrogate keys from operational primary keys for lifecycle isolation.
• Fact Grain: Explicitly defined as one land-cover measurement, for one satellite observation pass, in one region, on one calendar date. Enforced via database constraint uq_fact_grain.
